# Synthetic Data — Alderbrook University (Demo Dataset)

**All data in this directory is 100% synthetic.** "Alderbrook University,"
every student, advisor, faculty member, address, phone number, and incident
narrative was randomly generated by `scripts/generate_fake_data.py`. No real
people, real institutions, or scraped records were used at any point. This
dataset exists solely to power a demo student conduct / case-management
application.

The generator is deterministic (seeded with `SEED = 42`), so re-running it
produces the same dataset.

Regenerate with:

```bash
python3 scripts/generate_fake_data.py
```

---

## Files

| File | Records (typical run) | Source system |
|---|---|---|
| `students.csv` | 10,000 | Student Information System (SIS) |
| `housing.csv` | ~6,000–7,000 students housed (a few with 2 rows) | Housing / Residence Life |
| `campus_safety.csv` | ~700–1,000 | Campus Safety |
| `academic_integrity.csv` | ~400–500 | Academic Integrity Office |
| `reports.csv` | ~800–1,000 | Web / Anonymous Reporting Portal |

Exact counts vary slightly between runs because volumes are drawn from
ranges (e.g., "700–1,000 campus safety reports") rather than fixed numbers,
per the generator's realistic-distribution design. The student count is
always **exactly 10,000**.

## 1. `students.csv` — Student Information System (SIS)

The master roster. Every other dataset references students by `student_id`.

| Column | Description |
|---|---|
| `student_id` | Unique identifier, format `S000001`–`S010000`. Primary key. |
| `first_name` | Fictional first name. |
| `last_name` | Fictional last name. |
| `email` | Fictional university email, `firstname.lastnameN@alderbrook.edu`. Unique. |
| `dob` | Date of birth, consistent with the student's academic year (e.g., Freshmen skew 18, Graduate students 22–35). |
| `major` | One of ~30 fictional/generic academic majors. |
| `academic_year` | `Freshman`, `Sophomore`, `Junior`, `Senior`, or `Graduate`. |
| `enrollment_status` | `Enrolled` (~86%), `Graduated`, `Withdrawn`, or `Leave of Absence`. |
| `advisor` | Assigned advisor, drawn from a pool of 60 fictional faculty names. |
| `phone` | Fictional US-style phone number. |
| `address` | Fictional street address, city, state, and ZIP. |
| `enrollment_date` | Approximate first-enrollment date, derived from academic year. |

**Row count:** exactly 10,000. **Uniqueness:** `student_id` and `email` are
both guaranteed unique.

## 2. `housing.csv` — Housing / Residence Life

Housing assignments for a subset of the student body. Not every student
lives on campus (commuters, online, graduated, etc.), so this table is
intentionally a partial join against `students.csv`.

| Column | Description |
|---|---|
| `housing_id` | Unique identifier, format `H000001`. Primary key. |
| `student_id` | Foreign key → `students.csv:student_id`. |
| `residence_hall` | One of 15 fictional residence halls (e.g., "Birchwood Hall," "Sunrise Commons"). |
| `room_number` | Fictional room number. |
| `move_in_date` | Move-in date. |
| `move_out_date` | Move-out date, or blank if still `Active` / `Pending Assignment`. |
| `housing_status` | `Active` (~62%), `Moved Out` (~33%), or `Pending Assignment` (~5%). |

**Coverage:** ~6,000–7,000 distinct students have at least one housing
record (roughly 60–70% of the student body — realistic for a residential
university with commuter and online populations). About 8% of housed
students have a second row (e.g., a mid-year room change), so total row
count can slightly exceed the number of distinct students housed.

## 3. `campus_safety.csv` — Campus Safety

Incident reports logged by Campus Safety officers.

| Column | Description |
|---|---|
| `report_id` | Unique identifier, format `CS000001`. Primary key. |
| `student_id` | Foreign key → `students.csv:student_id`. Every value is a valid student. |
| `incident_date` | Date of the incident (within the last ~2 years). |
| `location` | Campus location (residence hall, quad, parking lot, academic building, etc.). |
| `incident_type` | e.g., Noise Complaint, Alcohol Policy Violation, Theft, Vandalism, Physical Altercation. |
| `severity` | `Low`, `Medium`, `High`, or `Critical`. |
| `status` | `Open`, `Under Investigation`, `Closed`, or `Referred to Conduct Board`. |
| `narrative` | Short synthetic narrative describing the incident. |

**Distribution:** ~700–1,000 total reports. The **large majority of
students (roughly 93%+) have zero campus safety records.** Of the students
who do have a record, most have exactly one; a smaller subset (~15–20% of
involved students) has two or more, simulating repeat-incident behavior.
Records are **not** evenly/randomly spread across all 10,000 students —
they are concentrated in a realistic minority.

## 4. `academic_integrity.csv` — Academic Integrity Office

Academic integrity case records.

| Column | Description |
|---|---|
| `case_id` | Unique identifier, format `AI000001`. Primary key. |
| `student_id` | Foreign key → `students.csv:student_id`. Every value is a valid student. |
| `course_code` | Fictional course code, e.g., `CS204`, `BUS317`. |
| `course_name` | Fictional course title matching the department. |
| `faculty_name` | Faculty member who filed the case (drawn from the same fictional faculty pool used for advisors). |
| `incident_date` | Date of the alleged incident. |
| `violation_type` | e.g., Plagiarism, Unauthorized Collaboration, Cheating on Exam, Unauthorized Use of AI Tools. |
| `severity` | `Minor`, `Moderate`, `Serious`, or `Severe`. |
| `status` | `Pending Review`, `Under Investigation`, `Resolved - Sanction Issued`, `Resolved - No Violation Found`, or `Appealed`. |
| `description` | Short synthetic description of the alleged violation. |

**Distribution:** ~400–500 total records, touching a small minority of
students (~3.5–4.5% of the student body). Most involved students have one
case; a smaller subset has multiple.

## 5. `reports.csv` — Web / Anonymous Reporting Portal

Reports submitted through a general-purpose web/anonymous reporting form.
This is the least structured source system: some reports name a student,
many do not (either because the reporter didn't know who was involved, the
concern doesn't involve a specific student, or the report was submitted
anonymously).

| Column | Description |
|---|---|
| `report_id` | Unique identifier, format `WR000001`. Primary key. |
| `reported_student_id` | Foreign key → `students.csv:student_id`, **nullable**. Blank when no student is identified. Every non-blank value is a valid student. |
| `reporter_type` | `Student`, `Faculty`, `Staff`, `Parent`, `Anonymous`, or `Community Member`. |
| `submitted_date` | Date the report was submitted. |
| `category` | e.g., Academic Dishonesty, Bullying/Harassment, Discrimination, Hazing, Sexual Misconduct, Safety Hazard, Bias Incident. |
| `location` | Location referenced in the report, or `Online / Remote`. |
| `priority` | `Low`, `Medium`, `High`, or `Urgent`. |
| `description` | Short synthetic description of the concern. |
| `anonymous` | `True`/`False` — whether the reporter chose to remain anonymous. |

**Distribution:** ~800–1,000 total reports. Roughly 55% identify a student
(`reported_student_id` populated); the rest are blank. Independently,
~35% of all reports are marked `anonymous = True` (an anonymous report can
still name a student, and a non-anonymous report can still omit one — the
two fields are not mechanically linked, matching how real reporting forms
behave).

## Relationships Between Datasets

```
students.csv (10,000 rows, student_id = PRIMARY KEY)
   │
   ├── housing.csv.student_id             (FK, required, ~60–70% coverage)
   ├── campus_safety.csv.student_id       (FK, required, small minority)
   ├── academic_integrity.csv.student_id  (FK, required, small minority)
   └── reports.csv.reported_student_id    (FK, NULLABLE, partial coverage)
```

- **Every** `student_id` appearing in `housing.csv`, `campus_safety.csv`,
  `academic_integrity.csv`, or `reports.csv` exists in `students.csv`.
  There are zero orphaned foreign keys.
- A student can appear in **zero, one, or multiple** source systems. A
  student with a campus safety report may or may not also have an academic
  integrity case, a web report, or a housing record — these are generated
  independently.
- Most students (roughly 85%+) have **no conduct-related record at all**
  across campus_safety, academic_integrity, and reports — only a housing
  record, if any. This mirrors a real university, where the overwhelming
  majority of students never appear in a conduct system.
- Within each incident-bearing dataset, a minority of students account for
  multiple records (repeat incidents), rather than incidents being spread
  evenly across the population — this is intentional and produced by the
  generator's weighted repeat-assignment logic (`assign_with_repeats` in
  the script), not uniform random sampling.
- `reports.csv.reported_student_id` is the only nullable foreign key,
  reflecting that anonymous/general-concern reports often don't name a
  specific student.

## Regenerating / Reproducibility

The script seeds both Python's `random` module and `Faker` with `SEED = 42`,
so re-running `python3 scripts/generate_fake_data.py` regenerates an
equivalent dataset each time (exact record counts within the specified
ranges may shift slightly only if the script itself is edited). The script
also runs its own internal verification (record counts, uniqueness, and
foreign-key integrity) before writing any CSVs and will raise an error and
exit non-zero if a check fails.
